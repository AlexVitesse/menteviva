  Qué construí

  Una versión chat-only aislada, que reusa exactamente el prompt y el LLM de
  producción pero sin nada más alrededor:

  Backend — menteviva-backend/app/routers/chat_text.py (+ registrado en main.py)
  - GET /api/chat/avatars → lista de avatares incluyendo a Sofia/entrevistador
  (la grilla normal lo esconde).
  - POST /api/chat → recibe {avatar_id, messages, greet, level?} y devuelve
  {reply, closing, prompt_chars}.
  - Por dentro solo llama get_system_prompt(...) + chat_complete(...) — cero 
  TTS, cero Gemini Live, cero análisis, cero DB. Es stateless: el cliente manda
  el historial completo cada turno.

  Frontend — menteviva-frontend/src/pages/ChatLab.tsx en la ruta /chat-lab (sin
  guard de onboarding, no toca el flujo de producto)
  - Dropdown para cambiar de avatar al vuelo, selector de nivel cuando aplica
  (Roberto).
  - Botón "Que inicie el avatar" (replica el saludo proactivo de prod vía un
  nudge interno), input de texto, burbujas.
  - Muestra el tamaño del prompt (chars) y un aviso cuando el avatar emite
  [CIERRE] — útiles para evaluar.

  Nada del producto cambia: si borras el archivo del router + su include_router
  y el Route, todo queda igual.

  Cómo probarlo

  ./start.bat        # o backend + vite por separado
  Luego abre http://localhost:5173/chat-lab. (El proxy de Vite manda /api/* al
  backend.)

  O directo por curl, sin frontend:
  curl -s localhost:8000/api/chat -H "Content-Type: application/json" \
    -d '{"avatar_id":"entrevistador","greet":true}'

  Dos notas importantes para que la evaluación sea fiel

  1. Esto evalúa el prompt por la ruta Groq (chat_complete → gpt-oss-20b), que
  es el prompt maestro de ~14k de Sofia. En producción de voz, Sofia corre por
  Gemini Live con un prompt conciso distinto
  (build_gemini_entrevistador_prompt). Si lo que quieres es validar el prompt
  que ven tus usuarios en voz, dímelo y agrego un toggle "prompt Groq (maestro)
  / prompt Gemini (conciso)" — un cambio chico.
  2. El endpoint es público (sin auth), igual que pediste para iterar rápido. No
  lo dejaría así en prod, pero para banco de pruebas local está bien.

  ¿Quieres que añada el toggle de prompt maestro vs. conciso, o lo dejamos en la
  ruta Groq por ahora?
